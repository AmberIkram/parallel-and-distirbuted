# Benchmarking Report

## Distributed GPU Offloading System — CSC-334

---

## Overview

This report analyzes the performance of offloading video rendering to a remote GPU-accelerated workstation compared to local CPU rendering. Results are generated by `benchmarks/benchmark.py` and stored in `benchmarks/results/`.

---

## Test Configuration

| Parameter | Value |
|-----------|-------|
| Input formats | MP4, MKV |
| Output format | MP4 (H.264) |
| Resolutions tested | Original, 720p |
| Bitrate | 4 Mbps |
| Preset | medium |
| Network | Gigabit Ethernet (LAN) |

**Test categories:**
- Small: ~10 MB
- Medium: ~50 MB
- Large: ~100 MB

---

## Metrics Collected

For each test run:

| Metric | Description |
|--------|-------------|
| Local render time | FFmpeg libx264 CPU render on the client machine |
| Upload time | Time to transfer the input file to the remote server |
| Remote render time | FFmpeg h264_nvenc (or libx264) on the remote machine |
| Download time | Time to transfer the output file back to the client |
| Total remote time | Upload + Render + Download |
| Network overhead | Upload + Download only |
| CPU usage % | psutil average during the operation |
| GPU utilization % | nvidia-smi average (if available) |
| Speedup factor | Local render time ÷ Total remote time |

## Analysis

### Why Remote Execution Can Be Faster

NVIDIA NVENC is a dedicated hardware encoder built into NVIDIA GPUs. Unlike libx264 (which uses CPU cores), NVENC offloads the encode pipeline to fixed-function hardware, freeing both the CPU and GPU compute cores. On a modern NVIDIA GPU:

- NVENC throughput can be 5–10× faster than libx264 on an equivalent CPU
- libx264 `medium` preset on a 4-core laptop may process 20–40 fps
- h264_nvenc on an RTX 3060 can process 200+ fps

The tradeoff is that NVENC produces slightly lower quality at equivalent bitrates compared to libx264 `slow`, but is indistinguishable from libx264 `fast` at the same bitrate.

### Network Transfer Impact

For a 100 MB input file on a Gigabit LAN (~100 MB/s sustained):
- Upload time: ~1.0 s
- Download time: ~0.5–1.0 s (output is typically smaller)
- Network overhead: ~1.5–2.0 s total

If the remote render time is 60 s locally vs 8 s on NVENC, the network overhead of 2 s still yields a **4.5× speedup**.

For very short videos (< 5 s clip) the network overhead may exceed the render time, meaning local rendering is faster. Offloading is most beneficial for:
- Videos longer than ~30 seconds
- High-resolution or high-bitrate transcoding
- Tasks requiring slow presets for quality

### CPU Fallback Performance

If the remote machine has no NVIDIA GPU, it uses libx264 (same as local). In this case:
- Remote render time ≈ Local render time
- Total remote time = render + network overhead > local time
- **CPU fallback is slower than local rendering**

The system clearly labels CPU fallback results. Remote CPU rendering is only beneficial when the remote CPU is significantly more powerful than the client (e.g., a 16-core server vs a 4-core laptop).

### When Offloading Is Beneficial

| Scenario | Beneficial? |
|----------|-------------|
| Remote NVENC + Gigabit LAN | Yes (4–10× speedup) |
| Remote fast CPU + Gigabit LAN | Marginal (1–2× if remote CPU is stronger) |
| Remote CPU + Wi-Fi | Usually not (network overhead too high) |
| Very short clips (< 10s) | No |
| Long videos (> 2 min) | Yes, especially with NVENC |

## Limitations

1. **Single-job queue** — The default configuration processes one job at a time. Multiple simultaneous clients must wait.

2. **No encryption** — HTTP/WebSocket traffic is plaintext. Suitable for trusted LAN demos only.

3. **File size limits** — Default 2 GB limit. Large files (> 1 GB) will have significant network overhead even on Gigabit Ethernet.

4. **NVENC quality** — h264_nvenc produces slightly different (not necessarily lower) quality compared to libx264 at the same bitrate. For archival quality, use libx264 slow.

5. **Windows-only batch scripts** — Server can run on Linux/macOS but the `.bat` scripts are Windows-only.

## Running Benchmarks

```cmd
:: Local only (no server needed)
run_benchmark.bat assets\demo\sample.mp4

:: Full comparison (local + remote)
run_benchmark.bat assets\demo\sample.mp4 192.168.1.1

:: Multiple files
python benchmarks/benchmark.py --input file1.mp4 file2.mp4 --server-ip 192.168.1.1
```

Results are saved as CSV, JSON, and PNG chart in `benchmarks/results/`.
